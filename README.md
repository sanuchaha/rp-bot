# RP Battle Tracker Bot

Telegram-бот — трекер состояния персонажей для RP и текстовых боёв. Готов к
бесплатному деплою на [Render](https://render.com) с хранилищем в
[Neon](https://neon.tech) (PostgreSQL).

## Возможности

- **До 5 персонажей на одного юзера**, у каждого: имя, класс, max/current HP.
- Меню управления `/persona`: список персонажей, выбор активного, добавление,
  редактирование ХП, удаление.
- Два класса:
  - ⚔️ Атакующий — урон 5% / лечение 5% (от макс. ХП).
  - 🌿 Лекарь — урон 15% / лечение 15% (от макс. ХП).
- Управление ХП в бою через команду `/fif` и inline-кнопки урона/лечения.
- При ХП ≤ 0 — персонаж выбывает («больница 🚑»). Финальное ХП сохраняется,
  восстановить можно вручную через `/persona`.
- **ХП НЕ восстанавливается автоматически** ни после боя, ни после дуэли —
  итоговое значение сохраняется в карточке.
- **Дуэли в группах** (`/duel @username` или `/duel` в ответ на сообщение
  игрока): дуэль идёт между активными персонажами обоих игроков. Бот в
  групповом чате ведёт общий статус и обновляет его при каждом действии.
- Все inline-кнопки **привязаны к владельцу** — чужие нажатия игнорируются
  (видят alert «Это не твой персонаж 🙅»).
- **Whitelist чатов**: переменная `ALLOWED_CHAT_IDS` ограничивает работу бота
  только указанными чатами.
- **Сохранение состояния**: Postgres (Neon) в проде, JSON-файл локально.

## Команды

| Команда | Что делает | Где работает |
|---------|------------|--------------|
| `/start` | Новый юзер — регистрация первого персонажа; иначе — открывает `/persona` | везде |
| `/persona` | Меню персонажей (список / добавить / редактировать ХП / удалить / выбрать активного) | везде |
| `/fif` | Открыть кнопки урона/лечения для **активного** персонажа | везде |
| `/duel @username` | Вызвать игрока на дуэль (между активными персонажами) | только группы |
| `/duel` (в ответ на сообщение) | Вызвать автора этого сообщения | только группы |
| `/help` | Список команд и правила | везде |

> Перед `/duel @username` оба игрока должны хотя бы раз написать `/start` боту
> — иначе бот не сможет связать username с user_id (это ограничение Telegram).

## Переменные окружения

| Переменная | Обязательная | Описание |
|------------|--------------|----------|
| `BOT_TOKEN` | да | Токен от [@BotFather](https://t.me/BotFather) |
| `ALLOWED_CHAT_IDS` | рекомендуется | Список chat_id через запятую — где боту разрешено работать. Пустое значение = бот отвечает везде. |
| `DATABASE_URL` | в проде | Postgres connection string из Neon. Если не задан — пишет в `data.json`. |
| `WEBHOOK_BASE_URL` | в проде | Базовый URL приложения, например `https://your-app.onrender.com`. Если не задан — бот работает long-polling'ом. На Render берётся из `RENDER_EXTERNAL_URL` автоматически. |
| `WEBHOOK_SECRET` | опционально | Секрет для проверки заголовка от Telegram. На Render выставляется автоматически (`generateValue: true`). |
| `WEBHOOK_PATH` | опционально | Путь для вебхука. По умолчанию `/tg/<bot_id>`. |
| `PORT` | автоматически | Порт HTTP-сервера. На Render проставляется платформой. |
| `RP_DATA_FILE` | опционально | Путь к файлу для fallback-хранилища (по умолчанию `data.json`). |

## Локальный запуск (для разработки)

```bash
pip install -r requirements.txt
cp .env.example .env
# отредактируйте .env: проставьте хотя бы BOT_TOKEN
export $(grep -v '^#' .env | xargs)
python bot.py
```

Без `DATABASE_URL` бот пишет в `data.json` (как было раньше).  
Без `WEBHOOK_BASE_URL` бот работает в режиме long-polling.

## Деплой на Render + Neon (бесплатно)

### 1. Создайте базу в Neon

1. Откройте [neon.tech](https://neon.tech) → Sign up → New project.
2. Скопируйте **Connection string** (формат
   `postgresql://user:pass@ep-...neon.tech/dbname?sslmode=require`).

Бесплатный план Neon даёт 0.5 GB storage и автостоп через 5 мин неактивности —
для трекера состояний этого с запасом.

### 2. Залейте код в GitHub

```bash
git init
git add .
git commit -m "RP bot ready for Render"
git branch -M main
git remote add origin git@github.com:YOUR_NAME/rp-bot.git
git push -u origin main
```

### 3. Создайте Web Service на Render

1. [Render Dashboard](https://dashboard.render.com) → **New +** → **Web Service**.
2. Подключите ваш GitHub-репозиторий с ботом.
3. Render увидит `render.yaml` и предложит создать сервис как Blueprint.
4. Заполните переменные окружения:
   - `BOT_TOKEN` — токен от BotFather
   - `DATABASE_URL` — строка из Neon (см. шаг 1)
   - `ALLOWED_CHAT_IDS` — chat_id вашей группы
     (отрицательное число вида `-1001234567890`)
   - `WEBHOOK_SECRET` — оставьте сгенерированное Render значение

При первом запуске бот:
- создаст таблицу `rp_bot_state` в Neon (DDL встроен в код);
- зарегистрирует webhook у Telegram на `https://<your-app>.onrender.com/tg/...`;
- начнёт принимать апдейты.

### 4. Узнайте chat_id вашей группы

Самый быстрый способ:

1. Добавьте в группу [@RawDataBot](https://t.me/RawDataBot) или
   [@getidsbot](https://t.me/getidsbot).
2. Напишите любое сообщение — бот ответит метаданными, включая `chat.id`.
3. Скопируйте `chat.id` (для супергрупп обычно `-100xxxxxxxxxx`) в
   переменную `ALLOWED_CHAT_IDS` на Render.

Альтернатива: посмотрите логи бота в Render — при попытке использования
нерешённого чата он логирует `Игнорирую апдейт из чата <id>`.

### 5. Тонкости free-tier

- **Render Free** засыпает после 15 минут без HTTP-трафика. При следующем
  апдейте Telegram разбудит сервис — первое сообщение может ответить с
  задержкой ~30 секунд (cold start). Telegram сам ретраит вебхуки до
  получения 2xx, так что апдейт не теряется.
- Если хочется убрать задержку — настройте [UptimeRobot](https://uptimerobot.com)
  пинговать `https://<your-app>.onrender.com/health` каждые 5 минут.
- **Neon Free** засыпает после 5 минут — первое обращение к БД на холодный
  старт тоже ~1 секунду подождёт. Это норма.

## Структура

- `bot.py` — весь код бота (aiogram v3, FSM, middleware для whitelist чатов,
  webhook/polling-режимы).
- `db.py` — слой хранилища: `PostgresStorage` (Neon / любой Postgres) или
  `FileStorage` (локальный JSON).
- `requirements.txt` — зависимости.
- `render.yaml` — конфигурация Render Blueprint.
- `Procfile`, `runtime.txt` — fallback для совместимости.
- `.env.example` — пример переменных окружения.

> Дуэли (как процесс) хранятся только в памяти — при перезапуске активные
> дуэли потеряются, но HP персонажей и сами карточки уцелеют.
